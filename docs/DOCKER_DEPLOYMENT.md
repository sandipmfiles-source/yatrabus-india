# YatraBus India — single-container deployment

This deployment runs the Express API and the built passenger web app from one Node.js container. The JSON repository is stored on a named Docker volume so it survives container recreation. This is a small single-instance deployment, not a multi-instance/PostgreSQL production architecture.

## 1. Prepare secrets

On the server, clone the repository and create a private environment file:

```bash
cp .env.example .env
chmod 600 .env
```

Set these values in `.env`:

- `ADMIN_EMAIL`: the one Super Admin email address.
- `ADMIN_PASSWORD_HASH`: a scrypt password hash generated by the repository's admin setup instructions.
- `ADMIN_JWT_SECRET`: a unique random secret of at least 32 characters.
- `GOOGLE_OAUTH_CLIENT_ID` and `OWNER_JWT_SECRET`: required to activate Owner Google sign-in.
- `VITE_GOOGLE_CLIENT_ID`: the same public Web Client ID, used at image build time.

Do not commit `.env`. Do not use a default password or a sample secret.

## 2. Build and start

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f yatribus
```

The service listens on port 5000 inside the container and is bound to `127.0.0.1:5000` on the host. Put it behind an HTTPS reverse proxy (Caddy, Nginx or a trusted tunnel) before public use. Do not expose the unencrypted port directly to the internet.

## 3. Health and persistence

```bash
curl -i http://127.0.0.1:5000/health
docker compose exec yatribus ls -l /app/data
```

Health returns `200 UP` only when the JSON persistence file is writable. The volume `yatribus-data` keeps state across container replacement. Back it up regularly:

```bash
docker run --rm -v yatribus-data:/data -v "$PWD:/backup" alpine sh -c 'tar czf /backup/yatribus-data-backup.tgz -C /data .'
```

Restore only after stopping the service and verifying the backup.

## 4. Build the Android APK against the deployed HTTPS host

In GitHub repository Settings → Secrets and variables → Actions → Variables, set:

- `VITE_API_BASE_URL` = `https://YOUR-DOMAIN/api`
- `VITE_GOOGLE_CLIENT_ID` = your Google Web Client ID (if Owner sign-in is enabled)

Then run the **Build Android APK** workflow. Android cleartext HTTP is disabled and native background GPS refuses to start without an HTTPS API base URL.

## Important limitations

- This deployment uses a single Express process and JSON-file storage. Do not run multiple replicas against the same JSON file.
- PostgreSQL migrations are present but the runtime PostgreSQL adapter is not connected.
- A successful container health check proves storage writability, not correctness of every bus timetable.
- Live GPS still needs physical Android testing, background-location permission, notification permission and a two-phone end-to-end test.
- Nationwide operator-verified bus schedules must be added and approved separately.
